# 清晰表达

适用于总结、分析和技术说明。用户指定格式时先满足该格式。

- 第一段给结论或问题的直接答案，然后解释依据。指导操作时先给能执行的一步。
- 用常见、具体的词。同一对象保持同一称呼。专业词首次出现时给短解释。
- 一句话处理一个主要意思，一段围绕一个主题。用主动语态说明谁做什么。
- 条件放在相关动作旁边。顺序操作用编号，横向比较可用表格。
- 首屏突出最相关的少数要点，详细证据放在后面。完整性要求优先，必要的限制和推导应保留。
- 只在确有未完成工作时给下一步。避免礼貌性重复、无关扩展和机械重述。
- 易读表达适用于所有读者。按用户反馈调整密度和篇幅，避免根据任务或语言推断健康状况。

正例（假设材料已证实）  
这个库适合把本地表格转成 HTML 报告。它只依赖 Node.js，部署简单。当前版本每次会重建整份报告，大文件需要先测处理时间。依据是 README 的运行要求和导出实现。

反例  
经过深入探索，这一极具潜力的方案充分体现了技术赋能，在多个维度有显著价值，建议进一步关注。

修改理由  
正例给出了用途、依赖和限制，读者可以据此判断是否试用。反例缺少可验证的信息。

这些中文规范借鉴 ASD-STE100 的通用写作原则、W3C 认知可访问性建议和社区 i-have-adhd 的部分表达方法。英语受控词汇及英语字数限制仅适用于其原规范。
