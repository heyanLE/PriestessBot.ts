# 总结与分析

阅读 [清晰表达](clear-writing.md)，再按用户问题组织内容。

## 两种档位

**轻量档（默认）**：因果关系、概念关系、优劣对比这类小问题。一句话结论 + 二到三条依据。不列要点清单，不附来源列表，不给取舍表。

**材料型**：用户指定了网页、文档或多份资料。先确认实际覆盖范围，再提取主张、比较维度和依据。

## 共用规则

先给用途或结论，再给影响判断的证据、限制和取舍。材料有版本和日期时保留。读不到全文时说清已读范围，不能把摘要当成全文。

材料型任务通常保留三到五个最相关要点，关键结论就近附来源。比较时统一维度；缺失项明确标为待核实。合理假设可以先写明再继续，只有缺失信息会改变结果时才追问。

正例（已读项目文档）  
项目用于在内网共享文件。部署需要一个容器和持久化目录。适合小团队临时交接；若需要审计下载记录，文档尚未说明这项能力。依据见部署章节和权限章节。

反例  
项目很先进，功能丰富，适合各种用户。要不要我帮你进一步分析？
