# Native local reminiscence

Native typed implementation informed by the pinned xkeyC/astrbot_plugin_local_reminiscence source (AGPL-3.0). The upstream Python plugin is not executed. The feature set includes per-sender scoped event narratives, event/day reflections, entity nodes, provenance-linked thematic summaries, recent/deep/node recall, real-time capture, daily model jobs, local embedding reindexing, and management inspection/deletion.

Every record retains platform, session type, session ID, sender and Agent. Private and group IDs cannot collide. Topics accept only currently owned event IDs; generated events/nodes accept only source transcript IDs actually supplied to the model. Neither a plugin setting nor a manager action creates higher sender privileges. Automatic job resume requires the saved owner grant version, state and session generation. Revocation, cancellation, disable and changed configuration prevent post-model commits. Failed summaries preserve old records. Daily records are replaced transactionally only after all chunk results validate. Manual node updates made during generation are retained.

Recording, automatic recall and daily scheduling are separately configurable and disabled by default. Recording requires `memory.write` and the `reminiscence_record` tool binding. Read tools require `memory.read`; write/summary/consolidation require `memory.write` and their corresponding bindings. Calls additionally respect per-tool approval settings. Summaries use the configured Agent model, so text will be sent to that configured model when a user enables or runs consolidation; local storage/local embeddings does not mean model summarization is offline.

Timezone and a daily hour/minute boundary define the logical day, including timezone/DST calendar handling. Closed days are processed per owner, each successful day once. Failed attempts retry no faster than hourly; restart-interrupted jobs are observable. Captured raw text is capped per message, per owner and by retention period. Summary input is chunked; normal tool/output content is never executed as code. No daily push or automatic session reset is implemented, and neither occurs implicitly.

`lexical` mode is honest local word/Chinese-character matching, not a semantic model. `local_endpoint` supports an already-running loopback HTTP(S), OpenAI-compatible `/v1/embeddings` endpoint and a configured model. It uses real returned vectors with bounded dimensions and shape validation; no local hashing is called semantic embedding. Old/unindexed records use labeled lexical fallback. Unavailable selected endpoints fail retrieval/index jobs rather than silently claiming semantic success. The loopback restriction means a Docker service must be within the same network namespace; remote embeddings are not offered by this plugin.

Differences from upstream: no SentenceTransformer/HuggingFace automatic model download, GPU management or embedding API server; no shared cross-session memory pool; no arbitrary external folder ingestion; no automatic reset/push; no random recall or persona-emotion simulation. Existing AstrBotX APLR databases are retained as source archives rather than guessed into a new permission scope. The UI exposes settings, scopes, source references, job failures, manual day consolidation, topic consolidation, reindex and day deletion. Deletion clears that day's transcripts and linked records/topics in the selected scope.
