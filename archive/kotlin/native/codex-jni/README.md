# PriestessBot Codex JNI bridge

This crate wraps the public Rust `engine` module in the sibling `codex_for_astrbot` checkout. It does not enable the fork's Python feature or start its app-server. The fork must be checked out beside the root PriestessBot checkout at revision `413f16a571a7a24557e70250c0284c5bebdd8c3f` before building.

Build with `sh native/codex-jni/build.sh` from the PriestessBot root; the script checks the fork revision and uses the checked-in Cargo lockfile. The output is `libpriestess_codex_jni.dylib` on macOS or `libpriestess_codex_jni.so` on Linux. For a local experiment, set `PRIESTESS_CODEX_EXPERIMENTAL=true`, `PRIESTESS_CODEX_JNI_LIB` to its absolute path, and `PRIESTESS_CODEX_JNI_SHA256` to the result of `shasum -a 256 <library>` (or `sha256sum` on Linux). Compile separately for the NAS CPU architecture; a macOS library cannot be copied to Linux.

The native API uses JSON for configuration, turns, events and tool responses. `pollEvent` returns `{ "status": "event", "sequence": 1, "event": ... }`, `{ "status": "timeout" }`, or a terminal status with a sequence. The caller dispatches an event and then calls `ackEvent(threadId, sequence)`. Until it does, polling repeats the same event. The Rust side owns a durable event pump for each thread, so timing out a JVM poll never cancels Codex's pending `next_event` call.

This source is an integration scaffold, not an enabled runtime feature. On macOS arm64 it has passed `cargo check`, `cargo build`, and the optional JVM smoke with a local mock Responses endpoint. The smoke covers a no-login turn, an authorized dynamic tool executed through `ToolCase`, a second turn with an empty tool manifest, persisted-rollout resume across an engine restart, and a fake-token scan of the Codex home while live and after shutdown. Codex core futures must run on the bridge's 16 MiB Rust worker threads; calling `Runtime::block_on` for resume on a JVM executor thread crashed at its smaller stack guard. Run the smoke with `PRIESTESS_CODEX_JNI_LIB=/absolute/path/to/libpriestess_codex_jni.dylib ./gradlew test --tests com.heyanle.priestess.bot.agent.codex.CodexNativeLoadSmokeTest`. NAS Linux packaging, crash/interrupt lifecycle tests, and a log-side credential audit still precede runtime activation.
