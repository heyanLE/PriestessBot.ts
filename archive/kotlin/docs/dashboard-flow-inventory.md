# Dashboard 操作流程与页面层级盘点

盘点日期：2026-10-28。范围为当前 TypeScript Dashboard 的 18 个主页面及其嵌套操作。结论来自组件、路由与服务端调用代码；没有浏览器截图或可用性测试，不能把这些结论当作视觉审计结果。此文档记录本轮优化前的事实与改造依据，后续实现应以实际代码为准。

## 1. 保存边界

当前操作分为三类。页面位置相邻不代表使用相同保存按钮。

| 类型 | 涉及内容 | 当前提交方式 | 生效与恢复边界 |
| --- | --- | --- | --- |
| 全局配置草稿 | 机器人、模型服务、Agent、授权、路由、执行环境、MCP、Skills、记忆库定义、知识库定义、Embedding/Reranker | `RuntimeConfig` 跨主页面共享；顶部“保存配置”统一校验并提交 `expectedRevision` | 服务端发布时取消运行中和排队任务、重新配置执行环境与平台。可导出草稿；恢复历史创建新修订。刷新浏览器有全局脏状态提醒，撤销、导入和退出原先没有同等保护 |
| 独立保存 | 人格正文、人格绑定、插件设置、搜索设置、原生扩展配置、记忆整理策略 | 各组件分别请求独立 API，通常有独立修订号 | 不由“保存配置”提交。部分组件持有本地编辑状态，离开页面卸载后可能丢失 |
| 立即操作 | 新建/发送会话、归档、停止任务、审批、记忆增删、知识导入、索引、文件操作、密钥、登录扫码 | 点击即请求对应 API | 不属于草稿。应显示“已提交 / 已完成 / 待处理”真实状态，危险操作说明具体对象与影响 |

代码依据：`dashboard/src/views/TypescriptRuntimeView.vue` 的 `install`、`publish`、`reload`、`rollback`、`protectDraft`；`typescript/apps/server/src/runtime.ts` 的 `publish`。

### 必须优先统一的语义

1. “保存配置”不代表保存当前页面所有内容。按钮应明确作用域，列出本次包含的配置页。
2. 服务端发布不是只影响后续消息：它会取消活动任务并重配环境。保存前应展示该影响，提交后确认结果。
3. 人格、搜索、插件、文件与消息各有自己的状态。全局配置显示“全部已保存”时，不能暗示这些独立编辑器也已保存。
4. “重新载入”会覆盖独立搜索表单；“选择另一个人格”会重置人格表单；进入其他主页面会卸载多个独立编辑器。应防止无提示丢失。
5. 保留版本冲突校验；冲突后保留用户输入，并提供查看服务端更新、导出当前输入、重新载入的明确入口。

| --- | --- | --- | --- | --- | --- |

## 3. 端到端流程

### A. 首次接入机器人

登录 → 保存服务端密钥 → 配置模型服务 → 创建并保存 Agent → 创建机器人并保存 → 检查连接/微信扫码 → 设置准入与默认路由 → 对目标发送者授权 → 草稿路由模拟 → 保存 → 实际消息 → 会话与执行记录。

成功定义应分开：连接在线、消息被接收、路由命中、模型完成、回复成功投递。不能以“机器人在线”替代后四项。

### B. 修改人格或上下文

选择人格 → 修改正文与示例 → 独立保存 → 绑定已保存 Agent → 预览生效提示词 → 修改 Agent 补充指令/上下文策略 → 保存全局配置 → 新轮次验证 → 查看对应执行。

必须显示两次保存的范围；预览明确采用“当前 Agent 草稿 + 已保存人格”。

### C. 装配工具或执行能力

配置插件/搜索/MCP/Skills/原生扩展/执行环境 → 保存或启用 → Agent 装配资源与工具 → Agent 能力与审批 → 发送者授权与资源范围 → 路由最高运行态 → 模拟授权 → 保存 → 实际调用 → 查看运行/后台进程/产物。

应在 Agent 显示缺失依赖入口与限制来源，而不是仅提供可勾选列表。人格限制仍会进一步收窄工具范围。

### D. 知识与记忆

知识：创建并保存知识库 → 导入文档 → 索引完成 → 检索验证 → Agent 装配 → 用户授权 → 实际对话引用。

记忆：创建并保存记忆库 → Agent 装配 → 选择手动写入或私聊自动提取 → 查看来源及作用域 → 生成整理预览 → 审核/应用 → 可选定期策略。群聊不会因打开私聊自动提取而自动共享记忆。

### E. 日常排障

机器人连接异常 → 机器人状态 → 对应凭据/连接设置；
机器人未回复 → 会话定位触发消息 → 执行节点路径 → 准入/授权/路由/模型/投递具体失败点；
任务运行缓慢 → 活动执行 → 工具事件/用量 → 后台进程 → 停止或审批；
文件未收到 → 工具实际结果 → 运行产物 → 投递事件 → 工作目录。

这是需要贯通的对象链：**平台消息 → 会话 → 运行 → 工具/进程 → 文件产物 → 回复投递**。目前跨页入口仅覆盖其中一部分。

### F. 配置维护与恢复

查看本次改动涉及的配置页 → 校验 → 查看活动任务影响 → 发布 → 确认状态；失败则保留草稿。
导出必须区分当前草稿与已保存配置。恢复先选择实际存在的修订、查看差异与影响，再生成新修订；不应要求用户凭记忆填写数字。

## 4. 页面层级优化建议

保留现有路由与 Agent 概念，按任务拆分导航职责，避免新增一层容器页面造成点击负担：

| 导航组职责 | 现有页面 | 页面内共同结构 |
| --- | --- | --- |
| 日常使用 | 概览、对话、会话管理、执行记录 | 先找到当前对象，再看状态与下一步；保持会话/运行上下文 |
| 助手设置 | 机器人、模型服务、Agent、人格库、消息路由、权限管理 | 列表 → 对象详情 → 常用设置；高级设置折叠，关联对象可跳转 |
| 能力与资料 | 插件、网络搜索、扩展、知识库、长期记忆、工作目录 | 当前状态 → 内容/设置；显示何处装配与何处使用 |
| 系统管理 | 执行环境、系统设置 | 运行状态与配置分开；凭据、审计、恢复均有明确边界 |

具体组名可由主导航统一实现；上述分组是信息职责建议。重要的是同页内不再混淆配置草稿、独立编辑和立即操作。
