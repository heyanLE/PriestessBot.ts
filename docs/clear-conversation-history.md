# 清空会话历史

这个操作清空全部平台和 Dashboard 的会话历史。人格、人格绑定、长期记忆、知识库、配置、附件文件和执行审计会保留。它不提供在线清空接口。

## 操作步骤

1. 构建本次版本：`npm run build:server`。
2. 先运行预览。预览只显示计数，不输出聊天正文、发送者 ID 或凭据。

   ```sh
   node dist/tools/clear-conversation-history.js --database /absolute/path/runtime.sqlite --dry-run
   ```

3. 停止机器人服务，确认没有其他进程使用该数据库。若仍有执行中、排队或待审批的任务，应先通过原服务停止任务，再停止服务。`--runtime-stopped` 是操作人的确认，工具不能代替进程检查。
4. 执行清空：

   ```sh
   node dist/tools/clear-conversation-history.js --database /absolute/path/runtime.sqlite --apply --runtime-stopped
   ```

5. 使用包含本次会话恢复修复的版本启动服务。检查会话列表为空，再用一条新的 IM 消息验证新会话可见。

## 数据边界

- 工具先使用 SQLite 在线备份接口创建完整、独立的备份，包含 WAL 中已提交的数据。备份文件不覆盖已有文件，权限为 `0600`，报告包含其路径。
- 清空范围是显式列表：管理会话、转录和任务关联；SDK 会话、旧动态上下文正文归档（`sdk-history-legacy-dynamic-archive`）、摘要缓存和用量锚点；旧暂停输入；群公开上下文和聊天搜索索引；续接种子和回执；后续输入；旧 AstrBotX 会话及平台消息/会话元数据归档；会话分组。遗留群历史键不是有效 JSON 时，跳过其代次解析，但仍清空记录。
- 原有墓碑保留。已删除会话新增墓碑。全部已知会话的 generation 推进到现有会话、执行记录、SDK 和群上下文所见的最大值之后，并记录恢复下限。保留的旧执行记录不能恢复到会话列表。新的消息使用新的 generation，不受旧墓碑阻挡。
- `runs`、`events`、投递记录、工具输出、审批记录和 `sdk-compactions` 等执行审计保留。它们可能仍包含执行时的输入或结果。因此，此操作不是全盘敏感数据擦除。
- 原始数据存在于备份中。其他来源数据库和磁盘附件不会被删除。工具不会调用 `RuntimeStore`，不会把执行中任务悄悄改为“已中断”。
- 删除、generation 推进、墓碑和报告在一个事务中完成。备份期间检测到其他连接提交，或写入失败时，清空事务回滚；已生成的备份保留。重复清空一个没有新历史的数据库不会再次推进 generation。

## 恢复

停止机器人及所有使用该数据库的进程后，通过 SQLite 备份接口把备份恢复到一个新的数据库文件，再将服务切换到新文件。不要在运行中覆盖数据库，也不要将旧的 `-wal`、`-shm` 文件与恢复文件混用。恢复会同时恢复备份时的配置和其他数据；执行前应确认备份时间。
