# NapCat 长回复防刷屏

在 Dashboard「机器人」中选择 NapCat 实例，在「消息防刷屏」设置合并转发字数阈值。保存后同时应用于该实例的群聊与私聊。

- 配置字段为 `forwardThreshold`，默认 `1500`，与 AstrBotX 的默认阈值一致；允许 `0` 至 `200000` 的整数，`0` 关闭自动合并转发。
- 按回复文本的 Unicode 码点数量计数，严格超过阈值才合并转发；恰好等于阈值仍按普通消息发送。
- 长回复以机器人身份组成合并转发节点，保留完整文本和图片，不再把长文本分页成多条普通消息。文件仍通过独立上传发送。
- 合并转发失败或发送结果未知时，不自动拆分重发，避免重复发送或再次刷屏。应查看投递错误后再决定是否重试。

普通回复中的连续文字、图片会按原有顺序放进同一条图文消息，群聊、私聊、审批恢复和插件回复均使用相同发送规则。图片先完成准备，再提交整条消息；不会先发送半条文字、随后因图片失败而留下拆散的回复。文件仍单独上传，文件前后的图文保持原顺序。

关闭合并转发或将阈值设得较高时，普通消息仍保留每条 3500 个 UTF-16 单位的文本预算；预算跨所有文字段累计，分页不切开 Unicode 字符，图片随其所在位置保留且不重复。超出合并转发阈值的回复继续使用转发卡片。

该设置仅改变 NapCat 的消息投递形式，不改变 Agent、权限、上下文或执行环境；NAS 的 SDK Docker 配置继续沿用。

自动化测试覆盖请求构造和阈值行为；这不代表已通过真实 QQ 客户端发送验收。
