# 模型结构预览与原位图文（2026-10-30）

## 模型输入与输出

Agent 记录默认展示结构化预览：系统指令、消息列表、可用工具与调用设置分开；用户/助手/工具消息和函数调用参数、结果按内容类型展示。可以切换格式化 JSON 或原始预览，复制的是脱敏后的审计预览。

新写入的 JSON 在节点内缩短长字符串、裁剪数组/深层对象，保留合法 JSON 结构。各顶层字段分配空间，模型 input 优先保留最近消息并说明省略了多少条。普通数组保留头尾。原始字符计数、是否截断与是否脱敏继续显示；不是完整、未脱敏的供应商原始请求。

旧记录如果已经被截成无效 JSON，会保留为文本并说明限制，不补造缺失字段。前端不执行 HTML，不加载 JSON 中的图片/链接；长文本与深层节点可展开，字符串、数字0、false和null不会混淆。

## NapCat 原位图文

NapCat 发送层原本支持有序文字/图片链；旧问题在上游将 Markdown 文字和渲染图片分开，再把图片追加到回复末尾。现在 Markdown 装饰器提供有序 parts，成功生成的图按其原始表格/公式块的位置插入；发送层、审批恢复、插件回复与会话存档消费同一顺序。

普通图文与合并转发都保留段落顺序。图片准备失败、取消或权限变化沿用原有失败与发送去重规则。渲染失败在原位使用既有文字回退；超过当前回复图片上限会在原位显示说明，不静默丢失。

`attach_file` 对本次 NapCat 回复中的图片返回 `inlineMarkdown`，例如 `![图片](artifact:图片ID)`。模型将该值放到最终答复中的目标位置后，由服务端按本次任务已登记产物解析。每张已附加图片最多发送一次；未指定位置的附件保留末尾发送行为。

仅当前回复已授权附加的图片可内嵌。其他任务的产物 ID、远程 URL、普通链接、字面 `[图 N]`、代码块/代码片段内的引用不会触发图片读取或发送。普通文件仍走独立上传。
