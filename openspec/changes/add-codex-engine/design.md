## Decisions

The JNI `cdylib` depends on `codex-astrbot-py` as an `rlib` with its Python feature disabled. The fork revision is pinned at `413f16a571a7a24557e70250c0284c5bebdd8c3f` and the bridge's lockfile carries the fork's dependency patches. The build script checks the checkout revision before producing a native artifact.

JNI methods accept and return bounded JSON. A native handle is a never-reused identifier into an `Arc` registry; closing the handle removes it before shutdown, while in-flight calls retain their own `Arc`. Rust panics are caught at the exported boundary and exceptions never include provider error text or credentials. Each loaded Codex thread has a bounded Rust event queue with sequence acknowledgement so cancellation after a JVM poll cannot discard an event.

Codex resume uses a deep native stack. A real JVM smoke crashed when `Runtime::block_on(Engine::resume_thread)` ran on a JVM executor thread with an approximately 2 MiB stack. Every core future now runs on the bridge's Tokio workers configured with 16 MiB stacks; JNI waits only for the result with a 120-second ceiling. Do not move this work back to the calling JVM thread.

The provider is a custom `wire_api = "responses"` connection with `requires_openai_auth = false` and an explicit bearer token. The token crosses the boundary in memory and is never passed to `login_api_key`. A fake token was absent from scanned Codex-home files both while a mock turn was active and after shutdown. Audit logs and target-platform behavior before authorizing real credentials.

The Kotlin runner has one generation per Agent home and a per-conversation mutex. Active turns hold a generation lease; a changed provider waits for old leases to drain before replacing the engine. A mapping keyed by hashed `(workspaceId, agentId, platformId, sessionId)` stores rollout path and hashes of provider and Agent model/instructions in an atomically replaced file. It stores no plaintext credential. A matching stored rollout resumes on the next process; changed provider, model or instructions start a fresh thread. An unusable rollout also starts fresh before any new turn is submitted. Both resets add a visible continuity notice to the next final response. The shared runner registry is registered through Koin and stopped after the message pipeline drains when the local experimental gate is enabled.

The isolated runner accepts `NONE` or `MULTI` routes. `NONE` submits an empty dynamic-tool manifest. `MULTI` derives declarations from the Agent's effective tool IDs, risk limits and sender permission, then binds that immutable set to the current turn. Each callback checks the live turn ID, namespace, call ID uniqueness and advertised name before `ToolCase.execute` rechecks arguments and permission. Unknown, stale or duplicate calls receive a failed result and interrupt the turn. Unexpected native approval requests are denied. A real JNI mock completed a tool call through `ToolCase` and then removed the declaration on a `NONE` turn in the same conversation. Configuration-time validation rejects native tool-name collisions, and the custom provider disables Codex's native web search. The executor returns the actual `last_agent_message` from `task_complete`, never fabricating a ChatProvider request/response pair. Trace correlation, complete skill delivery, NAS packaging and fault isolation still gate production use.

For a local experiment, `PRIESTESS_CODEX_EXPERIMENTAL=true` must be accompanied by an absolute `PRIESTESS_CODEX_JNI_LIB` path and its `PRIESTESS_CODEX_JNI_SHA256`. The Dashboard reports CODEX available only after path, OS suffix, architecture family and digest checks pass; Koin loads the library and registers the runner before processing messages. The custom provider disables Codex's own web search, and `no_environment` disables native execution tools. Only authorized Skill names are added to instructions; an authorized `use_skill` callback returns that Skill's bounded Markdown body to the model. `unload_skill` is not advertised because a persisted Codex transcript cannot forget an earlier tool result. Native turn and tool events are written to the execution trace as bounded metadata. A JNI thread-usage snapshot before and after each turn supplies real token deltas; a new thread's absent initial snapshot means zero. This local gate is not a NAS release qualification.
